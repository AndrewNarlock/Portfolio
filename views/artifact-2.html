Artifact 02

Infection

A real-time multiplayer tag game in the browser. One player starts out infected, and every survivor they touch joins them.

Overview

Infection is a game I built before this class. It has accounts, friends, private messages, lobbies of up to 30 players and per-player stats. For this artifact I rebuilt it with three goals: run leaner on both the server and the browser, add leaderboards using what I am learning in my algorithms class, and add new characters and game options.

The infected player moves faster than everyone else. The infected win if they catch every survivor before the timer ends; the survivors win if anyone is still uninfected.

Optimizations

I measured the original game with a benchmark script before changing anything. With three players, each one received 6,454 bytes per second even while everyone stood still, because every update (20 per second) re-sent every player's id, name, exact position and infected status.

  • Send only what changed. Names and infected status are sent once, when they change. Positions go out as a compact list of whole numbers with a short player number instead of a full id, and only when someone actually moved. Bandwidth dropped from 6,454 to 0 bytes per second while idle, and from 8,228 to about 1,000 while moving (87% less).
  • Draw only what is on screen. The 6000×4000 map is cut into tiles, and only visible tiles, buildings, trees and players are drawn. The old version kept a full copy of the map in memory, about 96 MB.
  • Do expensive work once. Building collision shapes and the scenery list are prepared once instead of on every check or frame, and the player sidebar is rebuilt only when someone joins, leaves or gets infected.

Leaderboards

There are leaderboards for survivor wins, infected wins and games played. The simple approach is to query the database and sort every player each time someone opens one, which is O(n log n) work per view. Instead, each leaderboard lives in memory and is only touched when a game ends.

  • A sorted array plus a hash map. The array keeps every player in order from best to worst, and the map finds any player's entry in constant time.
  • Binary search on updates. When a score changes, only that player moves: their entry is removed and re-inserted at the position binary search finds, so the list is never re-sorted.
  • Binary search for rank. A player's rank is one plus the number of players with a strictly higher score, found in O(log n). Tied players share a rank and are listed alphabetically.
  • A cached top 50. Each board keeps its top 50 ready to send and rebuilds it only after something changes, so viewing a leaderboard never touches the database.

Building this also uncovered bugs in how games were scored: infected players could never win, some games were never saved, and a player who disconnected during the countdown could still get a win. All three ways a game can end now go through one function that scores it.

New Features

  • New characters. Players used to be colored circles. They are now animated characters with a walk cycle, each with their own shirt color and skin tone. Infected players turn green and glow.
  • A full town. The map, buildings and trees come from my MMO project, Pebble Town. Players can't walk through buildings, and trees fade when you stand behind them.
  • Game length options. The lobby host picks 30 seconds, 1 minute, 5 minutes or 10 minutes. The server checks that the change comes from the host, before the game starts, and is one of the allowed lengths.

An end-to-end test runs the real server with three connected players and plays full matches to check scoring, leaderboards, collision and game length.
